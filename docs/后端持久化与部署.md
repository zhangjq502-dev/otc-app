# 后端持久化与部署

## 交付范围

Node.js 22+、Express、PostgreSQL。业务接口保持原有数据结构，前端登录和订单页面无需整体重写。持久化已通过本机真实 PostgreSQL 测试，尚未连接或更新线上服务。

本轮是小规模单服务的工程改造，不是经过审计的真实资金交易系统。行情仍由模拟引擎生成；真实收付款、商家操作台、入金与出金均未接入。

## 数据如何保存

| 表 | 内容 |
|---|---|
| app_users | 用户名唯一、密码 scrypt 哈希、资料、钱包绑定 |
| assets | 用户与币种复合主键、NUMERIC 可用和冻结余额、非负约束 |
| ads | 商家广告与库存 |
| orders | 用户归属、订单状态、到期时间、订单快照 |
| asset_ledger | 资产变动、关联订单、操作类型和时间 |
| idempotency_keys | 用户下单幂等键、请求参数及关联订单 |
| wallet_challenges | 一次性 nonce 与 5 分钟有效期 |
| schema_migrations | 当前结构版本 |

数据库表由服务启动初始化，使用事务锁避免同时初始化。用户、订单等业务字段部分存放 JSONB，余额独立使用 NUMERIC。不是所有字段都已完全规范化。

业务操作通过一个 PostgreSQL 事务更新用户资产、订单、广告库存和流水，失败则一起回滚。提交成功后才发布进程内订单事件，让 WebSocket 客户端看到已提交状态。

当前适配器加载领域状态，并使用数据库事务级 advisory lock 串行执行操作。它是便于验证一致性的保守方案，适合当前小项目，吞吐量有限。不能称为高并发撮合架构。当前 WebSocket 事件也只在本进程广播，部署保持单实例；多实例需进一步实现局部行锁、查询分页、消息总线/outbox。

订单扫描器每秒检查已持久化的状态与 expireAt，重启后立即执行一次恢复，不再只依赖 setTimeout。无服务运行期间不能执行动作，服务恢复后补处理到期订单。付款时也会校验是否超过期限。

## 安装依赖与本地运行

在项目的 server 目录执行：

```sh
npx --yes pnpm@12.4.2 install --frozen-lockfile
cp .env.example .env
```

把实际数据库连接串和密钥写入 `.env`，不提交 Git。start/dev 已通过 Node 的 env-file 参数加载该文件。

已有 PostgreSQL 时直接创建独立数据库并使用最小必要的数据库账号。也可使用 server/compose.yaml：先在终端环境设置 POSTGRES_PASSWORD，再运行 `docker compose up -d database`。该方案仅绑定本机端口，Docker 命名卷保存数据库数据，删除容器不等于删除卷，不要执行不必要的 `down -v`。

示例配置：

```dotenv
NODE_ENV=production
DATABASE_URL=postgresql://user:password@host:5432/otc
JWT_SECRET=替换为至少32字符的随机密钥
ADMIN_TOKEN=替换为另一组随机密钥
CORS_ORIGINS=https://你的前端域名
SEED_DEMO_DATA=false
SIMULATE_MERCHANT=false
TRUST_PROXY_HOPS=0
```

使用数据库提供商给出的 TLS 连接参数，不要通过关闭证书校验解决连接错误。用户名和密码含特殊字符时，需要按 URL 规则编码。

随后执行 `npm start`，日志应显示 `Storage: PostgreSQL`。健康检查 `/api/health` 会访问数据库；数据库不可用时不能报告健康。

生产模式缺少数据库连接或足够强的 JWT_SECRET 会拒绝启动，不会悄悄降级为内存存储。JWT_SECRET 应跨重新部署保持稳定，变更会使旧登录凭证失效。

## Render 现有服务怎么接

1. 创建或准备独立 PostgreSQL 数据库。先了解供应商的数据保留期限和费用，不能把短期免费实例当成永久存储。
2. 在现有 Web 服务的 Environment 中配置 DATABASE_URL，保留原来的 JWT_SECRET；额外设置 ADMIN_TOKEN。
3. CORS_ORIGINS 填实际浏览器前端域名，多个来源用英文逗号分隔。同域 H5 及原生 App 不依赖跨域白名单。
4. 单层可信代理可设 TRUST_PROXY_HOPS=1，使限流按客户端地址计算；不能无条件信任任意代理头。
5. 依照更新后的 render.yaml，用固定版本 pnpm 和锁文件安装，Start Command 保持 npm start。
6. 首次部署会创建所需表。若数据库账号无建表权限，需要管理员先执行同版本结构初始化，再用受限账号运行。
7. 注册一个新账号，再重新部署服务，检查账号能否登录、资产和历史订单是否保留。

本轮不会自动创建收费资源，也没有替你把本地代码推到线上。连接串仅配置服务器环境变量，不放前端、聊天或仓库。

## 演示行为开关与旧数据

生产默认不创建 demo 账号、不初始化模拟广告、不赠送注册资产，也不自动模拟付款/放币。空数据库首次打开没有广告和余额是预期结果；当前还没有正式商家开户、广告管理、充值及商家付款确认后台，需要另行实现，不能通过给任意注册用户增发余额代替。

仅为了隔离的技术演示，可显式设 SEED_DEMO_DATA=true 创建样例账号和广告。它只在用户表和广告表均为空时执行，不会每次启动重置数据。生产模式仍不会赠送模拟余额。开发模式可使用数据库并保留本地测试初始资产；不要让该数据库接触真实交易。

SIMULATE_MERCHANT=true 才会按持久化时间戳执行模拟商家动作。该选项不表示接入了任何真实支付渠道。

旧服务的内存状态不会自动迁移到 PostgreSQL；之前重启丢失的数据无法从代码仓库恢复。正式切换前若仍有需要保留的内存状态，应单独导出、校验并导入，不能直接声称历史数据已迁移。

## 下单重试

POST /api/otc/orders 支持 Idempotency-Key 请求头。相同用户、相同键和相同参数返回原订单；相同键用于不同参数返回 409。客户端应在一次下单意图内保留同一个键，用于网络超时后的重试；新的订单意图生成新键。当前旧前端没有自动发送此头，后端兼容旧请求，但不能把后端支持等同于前端已完成重试闭环。

## 安全与监控

密码原本已使用随机盐+scrypt 哈希，本轮保留此机制，没有明文存储。新增密码长度上限、登录注册限流、请求体大小限制、关闭 X-Powered-By、CORS 白名单、接口 no-store、WebSocket 消息大小与频道数量限制。

钱包 nonce 存入数据库，5 分钟有效，一次性消费和钱包写入在同一事务，避免服务重启后挑战状态丢失。钱包地址设置唯一索引。

生产 `/api/track/stats` 需登录且提供 X-Admin-Token；不要把管理员密钥打包进前端 App。当前内置监控页未做管理员凭据交互，生产普通用户访问会被拒绝。埋点仍为有限内存队列，重启清空；它不是财务记录。若需要历史监控需接独立日志/指标服务。

## 验证和备份

原接口测试：server 目录执行 `npm test`。

数据库集成测试：给 `TEST_DATABASE_URL` 指定可建临时 schema 的隔离测试数据库，再执行 `npm test`。测试会创建独立随机 schema，结束后删除，只应给测试库账号此权限。没有 TEST_DATABASE_URL 时数据库用例会跳过，不能据此认定数据库验证通过。

覆盖重启后持久化、幂等冲突、并发下单、资产/库存回滚、提交前不推送、过期恢复、nonce 单次消费和资产流水。当前通过的是本机测试，不等于线上验收。

上线前建立定期 pg_dump 或托管数据库备份，把备份保存在独立持久存储；定期做恢复演练。数据库持久化不会自动替代备份，也不能保证误删后可恢复。
